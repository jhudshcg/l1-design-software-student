3 · Make one edit, then check

  1. Find the guide’s marker in the named project file (Ctrl+F).
  2. Make one change and save (Ctrl+S).
  3. Refresh the project browser tab (Ctrl+R).
  4. Compare what happened with your prediction.

Something broke? In the edited file, undo the last change (Ctrl+Z), save and refresh. Then try a smaller edit. If you are unsure, keep your files and ask for help.

Need an older version?

Use the file Timeline or Source Control Graph to inspect an earlier checkpoint. Ask your teacher before restoring a version. Discard Changes removes saved edits since the last commit; it is not just Undo. Do not use it as a routine recovery step.

Help: testing the exact voucher boundary

If your menu cannot make £5.50, first test the fixed budget cases in Guide 3. For a whole-app boundary check, note an item’s original price, temporarily change it to 5.50, save/refresh and add just that item with promotion off. Check the warning. Repeat below/above. Restore the researched price, save/refresh and check the card again. Record both kinds of test. Do not leave test prices in your submitted menu.

5 · Reopen, review and hand in

  1. Save and close a project file. Locate and reopen it for your teacher (Task 10).
  2. Check against your plan. Record one strength and next step (Task 12).
  3. Submit the complete project folder and current booklet to your teacher’s hand-in location.

Keep HTML, CSS, both JS files, images and fonts together. An index.html file on its own is not the whole app. Acknowledge supplied code and support. You can submit with supplied working functions; unfinished extensions are not missing core design work.
